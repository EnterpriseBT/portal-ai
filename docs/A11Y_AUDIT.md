# Accessibility audit inventory

Every accessibility finding in Portals AI against **WCAG 2.2 AA**, mapped to a success criterion, to where it was seen (role, state, theme), and to the child of epic [#791](https://github.com/EnterpriseBT/portal-ai/issues/791) that owns the fix. It is the working list the area children (#793–#798) fix from, and the evidence the Accessibility Conformance Report (#800) is written from.

**Lifecycle.** This doc is durable: it's the evidence log for [`ACCESSIBILITY_CONFORMANCE_REPORT.md`](ACCESSIBILITY_CONFORMANCE_REPORT.md) (#800), whose rows cite its walk IDs (KB-nn, RZ-nn, SR flows). When the ACR's documentation-sync row fires, re-walk the affected flows here and record the result. It has no phase suffix, so a `/discovery` sweep leaves it alone.

## How it was produced

Until #799 the top of this doc was generated by `npm run a11y:report`, which ran jsx-a11y over the source, jest-axe over every Storybook story, and axe in Playwright across every app route (owner, admin and member; populated, empty, error, loading and locked; both themes) and every marketing-site page. **The last run (2026-11-13) found no automated findings in any tool:** 1,341 files linted, 483 stories rendered, 426 app-route runs and 24 site-page runs. Sixty app-route runs were skipped because the seeded org had no row to open on four detail pages.

#799 then removed the story sweep, the Playwright walks and the generator. They were slow, they needed a live seeded stack, and they flaked. What stays gated in CI:
- jsx-a11y's strict rules in `lint` (web, core, site);
- `component-axe.guard.test.ts` (web, core), which requires every component's own test to run `expectNoAxeViolations`;
- `theme-contrast.test.ts`, which holds both palettes at AA.

The **Keyboard pass** and **Screen-reader pass** below are hand-written and stay the inventory of what a person found. A row is closed by starting its Observed cell with "**Closed:**", saying what fixed it.

## Keyboard pass

Walked keyboard-only (no pointer), as owner and as member, through Playwright. Every flow is checked against:
- 2.1.1 keyboard
- 2.1.2 no keyboard trap
- 2.4.3 focus order
- 2.4.7 focus visible
- 2.4.11 focus not obscured
- 2.5.7 dragging movements
- 2.5.8 target size
- 3.3.7 redundant entry
- 3.3.8 accessible authentication

The flows:
1. Sign-in
2. CSV import → records
3. Station → portal → pin
4. A curated view
5. Settings → Members
6. Marketing site: home → pricing → contact

**Walked 2026-11-04**, keyboard only, in Chromium 1280×720 against the local stack and the `e2e-fixture` org (demo-seeded). The app was walked as owner and as member, the sign-in page and marketing site signed out. Tab order, focus indicators and obscured focus were recorded by script, with screenshots, and judged by eye. "Verify" marks a finding inferred from code that the owning child confirms before fixing.

**Checked and passing:**
- **No keyboard traps (2.1.2).** Every walked page's tab order completed a full cycle.
- **Dialogs keep focus (2.4.3).** New Station and Create View open from the keyboard, move focus into the dialog, and return it to their button on Escape.
- **Text fields show focus (2.4.7).** They get a clear ring.
- **The marketing site's skip link is the first stop (2.4.1).**
- **No obscured focus on the site (2.4.11).** The script flagged covered elements, but that came from sampling during a smooth scroll; the screenshots show nothing covered.

**Not exercised here:**
- **Redundant entry (3.3.7):** the import workflow is multi-step, so the screen-reader script walks it end to end.
- **Accessible authentication (3.3.8):** sign-in hands off to Google or Auth0, and our own page asks for no cognitive test.

**Maps and charts weren't reached:** the fixture org has no portal or pinned result (see Coverage).

## Resize, reflow, text-spacing and orientation pass

Added for the ACR (#800), since the keyboard and screen-reader passes don't check these criteria:
- 1.3.4 orientation
- 1.4.4 resize text
- 1.4.10 reflow
- 1.4.12 text spacing

**Walked 2026-11-13** in Brand and **re-walked 2026-11-14** in Brand Dark, by script in Chromium against the local stack and the `e2e-fixture` org, as owner. Both themes gave the same results. Each page was loaded at each condition and measured. Every hit was checked by screenshot, and visually hidden text (the skip link before focus, the collapsed user name, "(app version)") was ruled out by hand.

- **Reflow (1.4.10):** viewport 320×720. A failure is page-level horizontal scroll, or any element past the viewport's edge outside a scroll container. Tables, grids, code blocks, charts and maps are 2D content, which the criterion exempts, but their box must still fit the page.
- **Text spacing (1.4.12):** at 320×720, with line-height 1.5, letter-spacing 0.12em, word-spacing 0.16em and paragraph spacing 2em forced with `!important`. A failure is the same overflow, or text clipped by an `overflow: hidden` box.
- **Resize text (1.4.4):** at 1280×720, two checks. Root font size 200% (text-only zoom; the app's h1 measured 47→95px). Browser zoom 200% (a 640 CSS px viewport).
- **Orientation (1.3.4):** viewports 768×1024, 1024×768, 390×844 and 844×390. Also, no `orientation` media query, `screen.orientation.lock` or zoom-blocking viewport meta exists in `apps/web`, `apps/site` or `packages/core`.

**Pages:**
- **App:** dashboard, Stations and My Station, Entities and one entity's records, Connectors and two connector instances, Jobs and a job, Toolpacks, a column definition, Views (empty state), Settings, Help.
- **App, beyond pages:** the Edit Connector Instance dialog; the RegionEditor (File Upload wizard, Draw regions step, with `core-loop.csv`).
- **Site:** home, features, use cases and one use case, pricing, contact, security, privacy, terms.

**Not reached:** a portal with a chart or map. The fixture org's plan doesn't include the Visualize or GIS toolpacks, so none can be generated there. Charts and maps are 2D content for 1.4.10, and their "Show data" table is held by #796's tests.

## Screen-reader pass

Walk each flow below twice:
- **VoiceOver + Safari** on macOS: VO = Ctrl+Option. Open the rotor with VO+U to list landmarks, headings and links.
- **NVDA + Firefox** on Windows: browse mode is the default. H moves by heading, D by landmark, Tab by control, and Insert+F7 lists elements.

Use the local stack, signed in as the e2e owner (`e2e-fixture` org). Flow 5 is also walked as the member.

Each step says what you **do** and what you should **hear**. Anything you hear that differs, or anything you can't do without the mouse, is a finding. Record it in the table at the end as `SR-nn`, with the flow and step number, the AT you heard it with, and the owner: the area child that owns that part of the UI. If you're unsure of the owner, write `?` and it gets triaged. Two habits help:
- **Note when each page's title is announced.** A route change that announces nothing is a finding (2.4.2, 4.1.3).
- **Note when a toast or status change is announced.** Success and error toasts, job progress and lock alerts should be heard without moving focus to them (4.1.3).
