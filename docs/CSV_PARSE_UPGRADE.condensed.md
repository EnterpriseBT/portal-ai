# Upgrade csv-parse 6→7 (apps/api) — Condensed design (#550)

**Issue:** [EnterpriseBT/portal-ai#550](https://github.com/EnterpriseBT/portal-ai/issues/550) · Task · **small / condensed** (discovery + spec + plan + smoke in one doc).

**Why.** `npm audit` (via the #545 workflow) reports a **moderate** advisory against `csv-parse` (`<7.0.2`, prototype replacement reachable via the `columns` path — `GHSA-8cw4-87c7-c6xx`). `apps/api` pins `csv-parse@^6.2.0`; the fix is a major bump to `^7.0.2`. The one production usage streams in **array mode** and never touches the `columns` path, and the streaming API is unchanged across v6→v7, so this is a bump with **no code change**. Touches `apps/api` only. Clears the advisory outright (audit 17 → 16).

## Current shape

| Piece | Location | Note |
|---|---|---|
| Only csv-parse import | `apps/api/src/services/workbook-adapters/csv.adapter.ts:4` | `import { parse } from "csv-parse"` — streaming |

| Declared range | `apps/api/package.json:56` | `"csv-parse": "^6.2.0"` |
| Coverage | `apps/api/src/__tests__/services/workbook-adapters/csv-adapter.test.ts` | dedicated adapter suite (8 tests) |

## Decision — bump the range, no code change

`csv-parse@^6.2.0` → `^7.0.2`. v7's breaking changes are around the sync/`columns` surfaces and packaging; the streaming `parse()` + `.write()`/`.end()` + async-iteration contract the adapter relies on is unchanged, and the three options it passes all still exist. Verified by api type-check (would flag a removed/renamed option) + the adapter suite, not by editing code.

## Plan — 1 slice

**Files**

**Tests** — no new tests; a dep bump validated by existing suites. Run: `npm run build`, `npm run --workspace @portalai/api type-check`, `npm run lint`, the adapter suite (`--testPathPattern csv-adapter`), and the consumer suites (`--testPathPattern "file-upload|workbook"`). Green is the gate.
