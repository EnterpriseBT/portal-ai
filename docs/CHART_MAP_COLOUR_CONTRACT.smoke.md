# chart-map-colour-contract — Smoke Suite

Manual smoke test for [#1022](https://github.com/EnterpriseBT/portal-ai/issues/1022): agent-generated charts and maps take their colours from the theme's `dataViz` palette, held at 3:1, and tell categories apart by more than colour. **Branch under test:** `fix/1022-chart-map-colour-contract` (PR [#1031](https://github.com/EnterpriseBT/portal-ai/pull/1031)).

Steps tagged `— manual` need a human (visual judgment); `— backend` steps are a DB or log check outside the browser. Everything else is `/smoke-walk`-eligible. The charts and maps are generated by the live model, so the walk records what it saw rather than an exact picture.

## §1 — Chart colours and labels (acceptance 1, 2)

- [ ] In smoke-1022, Brand (light) theme, prompt: **"Chart total order amount by month as a line chart, one line per product category."**
- [ ] A chart renders (not the data-table fallback). Every `stroke`/`fill` colour on the chart's series marks (inside the chart iframe) is one of the light `dataViz.categorical` colours: `#1f6fb2 #c4580a #2e7d32 #b8326a #6f4bb0 #8a6d00 #00798c #a03a2c`. Record the set seen.
- [ ] Each series colour seen is ≥ 3:1 against the chart's background. Record the lowest ratio.
- [ ] The chart iframe's `body` background is `background.paper` (light `#faf9fe`).
- [ ] The series differ by more than colour: direct labels, dashes or marker symbols. Record which. — manual (judgment: whether a reader without colour can follow each series)
- [ ] A text legend or direct labels name every category. Record the names read.
- [ ] Switch to **Brand Dark**. The chart redraws in dark `dataViz` colours (`#6cb4ee #f5a35c #6fcf7a #f07fb0 #b99af0 #e6c84f #4fd1d9 #f28b78`), on a `#16162a` background. Record the set.

## §2 — The agent doesn't get to choose colours (acceptance 3)

- [ ] Prompt: **"Chart order count by product category as a bar chart, with bright red and blue bars."** A chart renders, and its bar colours are palette colours, not red or blue. Record them.
- [ ] `apps/api` log during §1–§2: count `visualize_d3 colour literal rejected` lines and record the literals. Zero is fine; any rejection must be followed by a chart or a data table, never an error. — backend

## §3 — Categorical map (acceptance 4, 5, 7)

- [ ] Brand (light). Prompt: **"Map the sites, coloured by type."**
- [ ] The legend reads **"Colour: type"** with 3 entries (`cross-dock`, `distribution-center`, `warehouse`, in the order the map lists them). Each swatch's colour is one of the first three light palette colours, and each has a 1px border.
- [ ] Each swatch colour is ≥ 3:1 against the Positron land colour `#fafaf8`. Record the ratios.
- [ ] Each point is drawn with a full-opacity 1px stroke (the "other" grey). Read it from the map's style (`circle-stroke-width` 1, `circle-stroke-color` `#6b7280`).
- [ ] "Features in view" lists each site with its `type`, e.g. "type: warehouse".
- [ ] Switch to **Brand Dark**. The basemap becomes Dark Matter, and the legend swatches change to dark palette colours. Record them.

## §4 — More than eight categories (acceptance 4, 7)

- [ ] Prompt: **"Map the sites, coloured by name."**
- [ ] The legend reads **"Colour: name"** with 8 named swatches, then a 9th swatch in "other" with **"+7 more, listed under Features in view"**.
- [ ] "Features in view" lists all 15 sites by name.

## §5 — A saved map recolours (acceptance 6)

- [ ] Take the §3 map's `portal_messages.blocks` entry of type `geo` (the one the widget renders; the `tool-result` beside it is the agent's copy) and rewrite its `content.spec.layers[0].style.colorBy` into the pre-#1022 shape: drop `categories` and set `stops` to `[["cross-dock","#4e79a7"],["distribution-center","#f28e2b"],["warehouse","#e15759"]]`. — backend
- [ ] Reload the portal. The map's legend shows theme colours, not `#4e79a7 #f28e2b #e15759`, in the order of the stored stops. Record them.

## §6 — Error & edge cases

- [ ] A polygon map isn't in the fixture, so the polygon outline (full-opacity category colour, 1.5px) is covered by unit tests only. Say so in the sign-off. — manual
- [ ] An OSM or custom basemap isn't verified (the ACR names it). No step.
