# Agent-guided browser sessions (Playwright harness) — Plan

**Sequenced implementation of the harness: `packages/e2e` + Playwright config + devcontainer browser bake, then the seed + auth fixtures, then the Playwright-MCP wiring, then the `/smoke-walk` skill, then the smoke-gate convention rewrite, then the proving walk.**

Spec: `docs/AGENT_BROWSER_SESSIONS.spec.md`. Discovery: `docs/AGENT_BROWSER_SESSIONS.discovery.md`. Issue: #304. No dependency on unshipped work.

Six slices, each leaving the repo compilable and Static Checks (`build`/`lint`/`type-check`) green at its boundary. They land as **commits on `feat/agent-browser-sessions`** — one feature, one PR (per `CLAUDE.md` → "Phase = commit, not PR").

**Verification is not jest** (automated specs are Out of scope — spec §Scope). This is a harness-enablement ticket, so each slice's "test-first" step names the concrete *check* that must pass before the change is real — a Static-Checks command, a config load-check, or an interactive agent/manual observation against the local stack. Where a slice has a script, run it from the package (never invoke jest/npx bare — `feedback_use_npm_test_scripts`):

```bash
npm run build && npm run lint && npm run type-check   # repo-root Static Checks — the standing gate
cd packages/e2e && npx playwright test --list          # config load-check (0 specs by design)
```

Sequencing rationale — the harness stacks bottom-up; each layer proves against the one below:

- **Slice 1** — the package + config + browser bake. Nothing runs yet; the check is Static Checks stay green and the config resolves.
- **Slice 2** — fixtures (seed + auth). Needs slice 1's package; produces the `storageState` slice 3 consumes. First slice that touches the running stack.
- **Slice 3** — MCP wiring. Needs slice 2's `storageState`; first slice where the agent drives a browser.
- **Slice 4** — `/smoke-walk` skill. Needs slice 3's browser tools; produces the evidence report.
- **Slice 5** — convention rewrite. References `/smoke-walk` (slice 4), so it lands after; otherwise independent (pure docs/skill edits).
- **Slice 6** — the proving walk (`docs/AGENT_BROWSER_SESSIONS.smoke.md`), which exercises slices 1–4 end-to-end and is this ticket's own merge gate.

No migration, no DB schema change, no app-source change (spec §Migration).

## Slice 4 — `/smoke-walk` skill + evidence-report format

The skill that turns a `.smoke.md` into a reviewable evidence report.

**Files**

- New: `.claude/skills/smoke-walk/SKILL.md` — invocation, preflight, per-step drive + classify, the evidence-report format (spec §Surface `/smoke-walk`).

**Steps**

1. **Check first (skill dry-run against a real `.smoke.md`).** The passing bar: `/smoke-walk` on an existing `docs/*.smoke.md` (e.g. one already in the tree, or a scratch one) runs preflight (stack/storageState/fixture reachability with the right remediation messages), walks each checkbox via `mcp__playwright__*`, and emits an evidence report classifying steps `verified` / `mismatch` / `could-not-automate` — **without editing the `.smoke.md` or checking any box**. A step it can't observe is `could-not-automate`, never `verified`.
2. **Implement** the skill markdown (preflight → per-step loop → classify → report to stdout + `packages/e2e/test-results/smoke-walk-<SLUG>.md`). Encode the hard rule: agent reports evidence, human checks boxes.
3. Dry-run the skill; inspect the produced report for the required distinctions.
4. No lint/type-check surface (markdown); confirm the skill is well-formed and discoverable.

**Done when:** `/smoke-walk` produces an evidence report on a real checklist, distinguishing verified from could-not-automate, and provably never checks a box.

**Risk:** the skill over-claims (marks `verified` without real observation). Mitigated by the explicit classification contract + the down-stack/could-not-observe rules; the report format forces an observed value per `verified` step.

## Cross-slice notes

- **`<PINNED>` version is one value in three places** — `packages/e2e` `@playwright/test` (slice 1), the Dockerfile `playwright@<PINNED>` (slice 1), and `.mcp.json` `@playwright/mcp@<PINNED>` (slice 3). Browser-build drift if they diverge; the in-file lockstep comment (mirroring the turbo-symlink convention) documents it. `@playwright/mcp` tracks `playwright` versions.
- **The browser bake needs a devcontainer rebuild to take effect.** The running container won't have Chromium until rebuilt (`~/.cache`/`/opt` aren't the bind-mounted `/workspace`). Slices 2–4 can be exercised interactively after a one-time local `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright npx playwright install chromium`; slice 6's proving walk must run **post-rebuild** to prove the image change itself. Flag this in the smoke preflight.
- **Operator prerequisite (not code):** a dedicated `e2e@` Auth0 user with **MFA disabled in the local/dev tenant**. Blocks slice 2's `e2e:auth`; documented in `packages/e2e/README.md`, not provisioned by this PR.
- **Secrets:** `E2E_AUTH0_USERNAME`/`PASSWORD` from the dev shell env only; `.auth/storageState.json` git-ignored. Never committed (spec Risks). The CI-secret path is the deferred ticket's job.
- **This whole ticket is partly doc-sync** (CLAUDE.md → "Keeping Documentation in Sync"): slice 5 is the convention/README update, landing in the same PR as the capability — not a follow-up.
- **No CI change.** No `test:e2e` workflow ships (deferred); the no-op `test:unit`/`test:integration` keep the existing turbo pipelines green. Static Checks is the only CI surface the new package touches.
- **CLAUDE.md compliance:** file/skill conventions (`*.config.ts`, `SKILL.md`), server-vs-prompt (n/a — no safety gate here), and the ephemeral-doc suffix (`.smoke.md` in slice 6) all hold.
