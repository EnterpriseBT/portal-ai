# Remove unused testcontainers devDeps (apps/api) — Condensed design (#552)

**Issue:** [EnterpriseBT/portal-ai#552](https://github.com/EnterpriseBT/portal-ai/issues/552) · Task · **small / condensed** (discovery + spec + plan + smoke in one doc).

**Why.** `npm audit` (via the #545 workflow) flags **moderate** advisories on `testcontainers` + `@testcontainers/postgresql` (via a vulnerable transitive `dockerode`→`uuid`). The ticket assumed an 11→12 **upgrade** — but the packages are **unused dead devDependencies**: nothing in the repo imports them, and the integration harness actually runs against the **docker-compose `postgres-test`** service. So the fix is to **remove** them, which clears all three advisories outright (better than upgrading) and drops the dead subtree. Touches `apps/api` only. Audit 16 → 13.

## Current shape

| Piece | Location | Note |
|---|---|---|
| Declared devDeps | `apps/api/package.json:84,102` | `@testcontainers/postgresql` + `testcontainers` `^11.12.0` — **the only tree contributors**; nothing else depends on them |
| Real integration harness | `apps/api/src/__tests__/__integration__/setup.ts:17-23` | `globalSetup` connects `postgres`/`drizzle` to `postgresql://…@postgres-test:5432` — **no testcontainers** |
| CI wiring | `.github/workflows/integration-test.yml:91,100` | `docker compose up -d postgres-test redis --wait`; `INTEGRATION_TEST_DATABASE_URL=…localhost:5433…` |
| Stale comments (13) | `apps/api/src/__tests__/__integration__/db/repositories/*.integration.test.ts` | JSDoc "spun up by testcontainers" — already wrong before this change |
| Imports of the packages | — | **none** anywhere in the repo (grep for `import`/`require` of `testcontainers` → 0 hits) |

## Decision — remove, don't upgrade

Delete both devDependencies. Evidence they're dead: (1) zero `import`/`require` across the repo; (2) `npm ls` shows them as sole self-rooted entries; (3) the harness demonstrably uses docker-compose. Removal is strictly better than an 11→12 bump — it eliminates `testcontainers` + `@testcontainers/postgresql` + transitive `dockerode` (and dockerode's `uuid` node) rather than carrying newer copies. Also fix the 13 stale JSDoc comments to name the real (docker-compose) harness, per the doc-sync rule.

## Plan — 1 slice

**Files**
- `apps/api/package.json` — remove the `@testcontainers/postgresql` and `testcontainers` devDependency lines.
- `package-lock.json` — regenerated by `npm install` (drops the testcontainers/dockerode/uuid subtree).
- `apps/api/src/__tests__/__integration__/db/repositories/*.integration.test.ts` (13) — replace "spun up by testcontainers." with "provided by the docker-compose postgres-test service (see `__integration__/setup.ts`)."

**Tests** — no new tests; a dead-dep removal. Validate: `npm run build`, `npm run type-check`, `npm run lint`. The **integration suite is the safety net** — it never imported testcontainers, so it must still pass on `docker compose up postgres-test` (runs in CI on a fresh `npm ci`).
